openchat▌

A serverless, end-to-end encrypted group chat that lives in a terminal. This page runs the real thing in your browser, minus the one part a browser cannot do.

! Real protocol, simulated transport. The message format, encryption, signatures, invites and ordering below are the production code, running unmodified. Peer discovery is not — there is no DHT in a browser, so other tabs and in-page members stand in for it.

Type anything and the room answers. The members replying to you hold their own Ed25519 keys and seal their own envelopes — your client verifies and decrypts every one of them the same way it would a stranger across the world.

What you are actually looking at

The line between real and simulated

Real, unmodified

  • Binary message encoding — compact-encoding, the same codecs the CLI writes to disk
  • AES-256-GCM encryption and Ed25519 signatures on every message
  • Invite strings — paste one from the CLI and this page will parse it
  • Causal ordering, so every member sees one transcript
  • Slash-command parsing and the whole chat view-model
  • Attachments: chunked, sealed per chunk, checksum-verified on arrival

Standing in

  • Peer discovery — Hyperswarm's DHT needs UDP; a BroadcastChannel carries frames between tabs instead
  • NAT traversal and Noise transport encryption, which the DHT provides
  • Replication — Autobase and Hypercore are native modules; history is re-sent on request here
  • Blob storage — Hyperblobs on disk becomes chunks in memory
  • The three members talking to you live in this page, not on other machines

Nothing you type leaves your browser. There is no server behind this page to leave to.

Two clients, one room

Open it twice

Every tab is a separate client with its own identity and its own copy of the room key. Open a second one and you are watching two real clients exchange sealed envelopes — the transport between them is a browser channel rather than the DHT, but nothing above that layer knows the difference.

How one codebase does both

What the browser borrows

The demo is honest because it is not a reimplementation. Everything above the transport is written once, with no Node or native dependencies, and imported by both front ends. A test fails the build if anything in that tier reaches for a Node built-in.

Shared
src/protocol/ · src/ui/model/
Message schema and codecs, the encrypted envelope, causal ordering, invite encode/decode, slash-command parsing, the chat state reducer.
CLI only
src/core/ · src/ui/ink/
Corestore, Hypercore, Autobase, Hyperswarm, Hyperblobs, sodium-native, and the Ink components that draw to a terminal.
Browser only
web/
The BroadcastChannel transport, the simulated members, and a DOM renderer that reads the same view-model the Ink components do.

The two crypto backends — sodium plus node:crypto on one side, WebCrypto plus @noble on the other — are held to byte-identical output by a test that makes each one decrypt what the other sealed. If the browser ever drifts from the CLI, the suite goes red.

Run the real thing: npm install && npm run build && node bin/openchat.js room create demo
Built on Hyperswarm, Hypercore, Autobase and Hyperblobs — the Holepunch stack.
